# Prácticas del Castillo de Luna

El **Castillo de Luna** guarda tesoros. Esta batería de prácticas es la que mandé en el curso
**2024/25**, cuando Desarrollo de Interfaces se peleaba con Java Swing, Scene Builder, JavaFX y
Launch4j. El backup de Moodle de aquel curso ha sido desenterrado, y cada práctica ha sido
**adaptada una a una** al stack de este curso: **Android Studio + Jetpack Compose**.

La regla de adaptación ha sido conservar la **intención didáctica original** de cada ejercicio
(qué competencia entrenaba) y traducirla a la tecnología actual. Los enunciados mantienen la
estructura de siempre: ejercicios numerados, consejos y las normas de entrega.

## Índice de prácticas

| Nº | Título original (24/25) | Versión Castillo (Compose) |
| -- | ----------------------- | -------------------------- |
| 1 | Introducción a la confección de interfaces (MonoDevelop/NetBeans/Eclipse) | El entorno Android Studio y los casos prácticos de la UD2 |
| 2 | Clases y componentes (Java Swing) | Login, calculadora y formulario personal |
| 3 | Generación de interfaces a partir de XML (Scene Builder) | De layout XML clásico a Compose |
| 4 | Creación de componentes (JavaFX + .jar) | Componentes reutilizables en Compose |
| 5 | Explotación de componentes visuales (JUnit) | Pruebas unitarias con JUnit en Android Studio |
| 6 | Usabilidad I | Usabilidad I sobre tus apps Compose |
| 7 | Usabilidad II: pautas de diseño | Usabilidad II: patrones Material |
| 9 | Confección de informes II (BIRT) | Listados y exportación de datos |
| 10 | Documentación de aplicaciones: ayudas | Documentación de aplicaciones |
| 11 | Distribución de aplicaciones (JAR/Launch4j) | Distribución: APK, AAB y firma |
| 12 | Realización de pruebas | Realización de pruebas y depuración |

> No existe la práctica 8: en su día el tema 8 (bases de datos embebidas) no llevaba práctica
> asociada, y se mantiene la numeración original para que podáis rastrear el linaje de cada una.

## Normas comunes de entrega

- Las prácticas se entregan en **PDF** con capturas del proceso.
- Captura válida: descriptiva, con tu usuario visible y la fecha del sistema, sin montajes.
- El código que aparezca, comentado línea a línea (como escribís por WhatsApp, pero con
  ortografía técnica).
- Retraso = 1. Sin excepciones, como siempre.
